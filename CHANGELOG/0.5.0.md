# 🔧 CHANGELOG - v0.5.0

## 📋 Résumé

**Implémentation majeure : injection Rust (DLL) pour le contrôle des instances Dolphin sans impact sur l'OS ni sur les autres agents.**

Avant cette version, les inputs étaient envoyés via vgamepad/HidHide, ce qui nécessitait ViGEmBus, HidHide, et un focus fenêtre. Les touches injectées traversaient la pile OS et pouvaient interférer avec le vrai clavier/souris. Cette version remplace entièrement ce système.

---

## ✅ 1. DLL Rust — Injection DInput (`dolphin_input_hook.dll`)

### Avant (v0.1.x)
```python
# Dépendances lourdes, focus fenêtre requis
import vgamepad
gamepad = vgamepad.VX360Gamepad()  # Nécessite ViGEmBus
# Les inputs traversent la pile OS → affecte le vrai clavier
```

### Maintenant (v0.5.0)
```rust
// hook/src/lib.rs — Hook DInput GetDeviceState directement dans Dolphin
// Les bytes sont écrits dans une shared memory par PID
// Dolphin lit les inputs depuis sa propre mémoire → jamais l'OS réel
unsafe extern "system" fn hooked_GetDeviceState(
    this: *mut (),
    cb_data: u32,
    lpv: *mut u8,
) -> i32 {
    // Keyboard (cb_data=256): injecter depuis shared memory
    // Mouse (cb_data=16/20): axes via orig, boutons depuis shared memory
}
```

**Impact :**
- ✅ Aucune dépendance ViGEmBus / HidHide / vgamepad
- ✅ Pas besoin de focus fenêtre Dolphin
- ✅ Les agents peuvent tourner entièrement minimisés
- ✅ Les inputs réels de l'utilisateur NE SONT PAS envoyés aux agents

## ✅ 2. Mémoire partagée par PID (`DolphinInputHook_SharedMem_<PID>`)

### Architecture
```
Shared Memory Layout (280 bytes) :
  [0..255]   keyboard DIK scan codes (1 = pressé, 0 = relâché)
  [256..263] boutons souris (mouse_left, mouse_right...)
  [264..279] réservé / unused

Un canal séparé par instance Dolphin (PID unique)
→ Agent 0 écrit dans SharedMem_PID_0
→ Agent 1 écrit dans SharedMem_PID_1
→ Aucune collision possible
```
