# 🔧 CHANGELOG - v1.0.0

## 📋 Résumé

**Révision totale du système d'envoi d'actions.** L'ancien espace discret `Discrete(19)` forçait l'agent à choisir une unique action par step, l'empêchant d'effectuer simultanément plusieurs mouvements (bouger + tourner la caméra + attaquer). Il est remplacé par un système **multi-heading** : 7 têtes indépendantes à espace `MultiDiscrete`, combinables librement à chaque step.

---

## ✅ 1. Remplacement de `Discrete(19)` par `MultiDiscrete([5,5,5,2,3,8,2])`

### Avant (v0.x.x)
```python
# Un seul choix parmi 19 actions exclusives
action_space = spaces.Discrete(19)
# action=0  → NOOP
# action=1  → avancer
# action=5  → caméra haut
# action=9  → attaque 1
# → Impossible d'avancer ET d'attaquer dans le même step
# → Impossible de tourner la caméra en se déplaçant
# → L'agent doit choisir entre bouger et combattre
```

### Après (v1.0.0)
```python
# 7 têtes indépendantes, toutes activables simultanément
ACTION_BRANCHES = [5, 5, 5, 2, 3, 8, 2]
action_space = spaces.MultiDiscrete(ACTION_BRANCHES)

# HEAD_MOVEMENT    [5]  nothing | forward | backward | strafe_L | strafe_R
# HEAD_CAMERA      [5]  nothing | up | down | left | right
# HEAD_COMBAT      [5]  nothing | attack | dodge | draw_sheath | kick
# HEAD_USE_ITEM    [2]  nothing | use
# HEAD_SELECT_ITEM [3]  nothing | radial_left | radial_right
# HEAD_MENU        [8]  nothing | start | nav_up | nav_down | nav_left | nav_right | confirm | back
# HEAD_SPRINT      [2]  nothing | sprint

# → L'agent peut avancer + tourner caméra + attaquer dans le même step
# → Combinaison naturelle comme un joueur humain
```

## ✅ 2. `action_heads.py` — Définition des 7 têtes

Fichier central qui décrit l'intégralité de l'espace d'action multi-heading : indices, branches, mapping vers les touches physiques, priorités, et matrice de compatibilité.
```python
# core/controller/action_heads.py

# ── Indices ──────────────────────────────────────────────────────────
HEAD_MOVEMENT = 0 ; HEAD_CAMERA = 1 ; HEAD_COMBAT      = 2
HEAD_USE_ITEM = 3 ; HEAD_SELECT_ITEM = 4 ; HEAD_MENU   = 5 ; HEAD_SPRINT = 6

# ── Mapping tête → branche → touches physiques ───────────────────────
HEAD_KEYS = {
    HEAD_MOVEMENT:    {1: ['w'], 2: ['s'], 3: ['a'], 4: ['d']},
    HEAD_CAMERA:      {1: ['up'], 2: ['down'], 3: ['left'], 4: ['right']},
    HEAD_COMBAT:      {1: ['mouse_left'], 2: ['mouse_right'], 3: ['p'], 4: ['m']},
    HEAD_USE_ITEM:    {1: ['q']},
    HEAD_SELECT_ITEM: {1: ['shift', 'left'], 2: ['shift', 'right']},
    HEAD_MENU:        {1: ['e'], 2: ['up'], 3: ['down'], 4: ['left'],
                       5: ['right'], 6: ['mouse_left'], 7: ['mouse_right']},
    HEAD_SPRINT:      {1: ['ctrl']},
}

# ── Priorités de résolution de conflits ──────────────────────────────
# En cas d'incompatibilité entre deux têtes actives,
# la tête de plus haute priorité garde sa valeur, l'autre est forcée à 0.
HEAD_PRIORITY = {
    HEAD_MENU:        60,   # Menu écrase presque tout
    HEAD_USE_ITEM:    50,   # Utiliser un item très restrictif
    HEAD_COMBAT:      40,   # Combat bloque sprint, sélection, menu
    HEAD_SELECT_ITEM: 30,   # Sélection item bloque caméra et combat
    HEAD_SPRINT:      20,   # Sprint bloque combat et menu
    HEAD_CAMERA:      10,   # Caméra presque toujours autorisée
    HEAD_MOVEMENT:     0,   # Mouvement toujours autorisé
}

# ── Matrice de compatibilité ─────────────────────────────────────────
# COMPAT[h] = ensemble des têtes compatibles avec h quand h est actif.
# La matrice est symétrique : si B ∈ COMPAT[A], alors A ∈ COMPAT[B].
COMPAT = {
    HEAD_MOVEMENT:    {HEAD_MOVEMENT, HEAD_CAMERA, HEAD_COMBAT,
                       HEAD_SELECT_ITEM, HEAD_MENU, HEAD_SPRINT},
    HEAD_CAMERA:      {HEAD_MOVEMENT, HEAD_CAMERA, HEAD_COMBAT,
                       HEAD_USE_ITEM, HEAD_SPRINT},
    HEAD_COMBAT:      {HEAD_MOVEMENT, HEAD_CAMERA, HEAD_COMBAT},
    HEAD_USE_ITEM:    {HEAD_CAMERA, HEAD_USE_ITEM},
    HEAD_SELECT_ITEM: {HEAD_MOVEMENT, HEAD_SELECT_ITEM, HEAD_SPRINT},
    HEAD_MENU:        {HEAD_MOVEMENT, HEAD_MENU},
    HEAD_SPRINT:      {HEAD_MOVEMENT, HEAD_CAMERA, HEAD_SELECT_ITEM, HEAD_SPRINT},
}
```

## ✅ 3. `action_resolver.py` — Pipeline de résolution en 3 étapes

À chaque step, avant tout envoi de touches, le vecteur brut de l'agent passe par ce pipeline garantissant un état toujours cohérent avec les règles du jeu.
```python
# core/controller/action_resolver.py
class ActionResolver:
    def resolve(self, raw_action, *, menu_open: bool = False):
        resolved = np.array(raw_action, dtype=np.int32).copy()

        # Étape 0 : Zéroter les têtes désactivées (ex : HEAD_MENU par défaut)
        for head_idx in self._disabled_heads:
            resolved[head_idx] = 0

        # Étape 1 : Gate menu
        #   menu ouvert  → seules Movement et Menu restent actives, tout le reste → 0
        #   menu fermé   → Menu ne peut valoir que 0 (rien) ou 1 (start), pas de navigation
        self._apply_menu_gate(resolved, menu_open)

        # Étape 2 : Résolution des conflits par priorité
        #   trier les têtes actives par HEAD_PRIORITY décroissant
        #   pour chaque tête : si elle n'est pas dans COMPAT de toutes les têtes
        #   déjà acceptées → forcée à 0
        self._resolve_conflicts(resolved)

        # Étape 3 : Collecte des touches physiques
        keys = self._collect_keys(resolved)

        return resolved, keys
```

**Exemple de résolution :**
```
Vecteur brut   : [1, 3, 1, 0, 0, 0, 1]
                  fwd cam← atk       sprint

Étape 2 — COMBAT (priorité 40) et SPRINT (priorité 20) :
  SPRINT not in COMPAT[COMBAT] → sprint forcé à 0

Vecteur résolu : [1, 3, 1, 0, 0, 0, 0]
Touches        : {'w', 'left', 'mouse_left'}
```

## ✅ 4. `key_state_manager.py` — Paradigme hold/release (diff engine)

L'ancien système tapait et relâchait chaque touche à chaque step, causant des mouvements hachés et des déplacements saccadés. Le nouveau système ne modifie que les touches qui **changent** entre deux steps : les touches identiques restent maintenues sans aucune interruption.
```python
# core/controller/key_state_manager.py
class KeyStateManager:
    def apply(self, desired_keys: set):
        to_release = self._currently_held - desired_keys  # libérer ce qui disparaît
        to_press   = desired_keys - self._currently_held  # presser ce qui arrive
        # intersection → rien à faire, touches maintenues

        for key in to_release: self._release(key)  # release d'abord (évite ghost combos)
        for key in to_press:   self._press(key)

        self._currently_held = set(desired_keys)
```

**Exemple concret — déplacement sur 50 steps :**
```
Step  1 : desired={w, shift}  held={}       → press w, press shift
Step  2 : desired={w, shift}  held={w,shift}→ rien (w et shift maintenus)
Step  3 : desired={w}         held={w,shift}→ release shift (w reste)
...
Step 50 : desired={}          held={w}      → release w
```
Avec l'ancien système : 50 × (press w + release w) = 100 appels, mouvement saccadé.
Avec le nouveau : 2 appels totaux pour w, mouvement parfaitement fluide.

## ✅ 5. `wii_controller.py` — Touches éphémères (tap) vs persistantes (hold)

Certaines actions nécessitent un *rising edge* à chaque step : les maintenir plusieurs frames consécutives provoque leur ignorance par le jeu. Elles sont séparées des touches de mouvement qui doivent au contraire rester maintenues.
```python
# core/controller/wii_controller.py

# Touches qui doivent être tapées (press + release) à chaque step où elles sont actives.
# Les maintenir bloque le jeu (pas de deuxième coup sans relâchement).
EPHEMERAL_KEYS: frozenset = frozenset({
    'mouse_left',   # Attaque   — 1 tap = 1 coup | confirm menu
    'mouse_right',  # Esquive   — 1 tap = 1 roulade | retour menu
    'e',            # Menu      — 1 tap = ouvre/ferme (toggle)
    'q',            # Item      — 1 tap = 1 utilisation
    'p',            # Arme      — 1 tap = dégainer/rengainer (toggle)
    'm',            # Coup pied — 1 tap = 1 coup | zoom/fermer carte
})

def execute_action(self, action_vector, *, menu_open=False, step_duration=0.080):
    resolved, desired_keys = self._resolver.resolve(action_vector, menu_open=menu_open)

    tap_keys  = desired_keys & EPHEMERAL_KEYS   # → tap-and-release dans ce step
    hold_keys = desired_keys - EPHEMERAL_KEYS   # → maintenues entre les steps

    # Hold : seulement les touches qui changent sont envoyées
    self._key_manager.apply(hold_keys)

    # Tap : durée adaptative (70% du step, clamped entre 25 ms et 80 ms)
    # En multi-instance (step=33ms) : ~25ms
    # En single-instance (step=80ms) : ~56ms
    tap_duration = max(0.025, min(0.080, step_duration * 0.70))
    if tap_keys:
        for key in tap_keys: self._press(key)
        time.sleep(tap_duration)
        for key in tap_keys: self._release(key)
        time.sleep(max(0.0, step_duration - tap_duration))
    else:
        time.sleep(step_duration)

    return resolved, step_duration
```

## ✅ 6. `--disabled-heads` — CLI pour désactiver des têtes

La tête `menu` est désactivée par défaut pour éviter que l'agent ouvre accidentellement les menus en phase de combat. Toute tête peut être désactivée ou réactivée via CLI.
```python
# train/cli.py — groupe 'Action heads'
g_heads.add_argument(
    '--disabled-heads',
    nargs='*',
    default=['menu'],
    choices=['movement', 'camera', 'combat', 'use_item', 'select_item', 'menu', 'sprint'],
    help='Action heads to disable. Pass with no argument to enable all heads.'
)

# Exemples :
# python train.py                                   → menu désactivé (défaut)
# python train.py --disabled-heads menu use_item    → menu + use_item désactivés
# python train.py --disabled-heads                  → toutes les têtes actives
# python train.py --disabled-heads sprint           → sprint désactivé uniquement
```

Les têtes désactivées sont passées au `WiiController` qui les convertit en `frozenset` d'indices et les transmet à `ActionResolver`. Leur valeur est systématiquement forcée à 0 avant toute autre résolution.

## ✅ 7. Compatibilité descendante — `execute_legacy_action()`

L'ancien dispatch `Discrete(19)` est conservé dans `WiiController` pour permettre une migration progressive sans casser les scripts existants.
```python
# core/controller/wii_controller.py
def execute_legacy_action(self, action_id: int, frames: int = 10) -> int:
    """
    Exécute une action de l'ancien espace Discrete(19).
    Utilise tap-and-release simple, sans le système hold/release ni les têtes.
    Conservé uniquement pour compatibilité ascendante — ne pas utiliser dans
    de nouveaux scripts.

    action_id :  0 → NOOP
                 1 → avancer ('w')
                 2 → reculer ('s')
                 3 → strafe gauche ('a')
                 4 → strafe droit ('d')
                 5 → caméra haut ('up')
                 6 → caméra bas ('down')
                 7 → caméra gauche ('left')
                 8 → caméra droit ('right')
                 9 → attaque 1 ('4')
                10 → attaque 2 ('1')
                11 → dégainer ('3')
                12 → back ('0')
                13 → menu ('e')
                14 → z-target ('ctrl')
                15 → sprint ('shift')
                16 → utiliser item ('q')
                17 → sélection item gauche (shift+left)
                18 → sélection item droite (shift+right)
    """
```
